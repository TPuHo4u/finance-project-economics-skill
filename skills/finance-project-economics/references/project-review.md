# Проверка проекта и план-факт

Основа: FEO, с. 21–26, 28, 32; HW, с. 4–11; AI, с. 3, 5–7. Это практический порядок составителя по материалам курса.

## До запуска

Сформулируй гипотезу: «Если изменим X у этой группы, драйвер Y изменится относительно базы Z, что даст денежный результат M за период H». Зафиксируй владельца результата и данных. Для неопределённой связи выбери пилот, который отвечает на конкретный вопрос: например, приведёт ли сокращение времени к уменьшению внешних закупок без ухудшения качества.

План измерения: единица наблюдения, период до/после, контроль/сопоставимая группа при возможности, сезонность, объём выборки/достаточность данных, параллельные изменения, лаг, критерии качества и решение по итогам. Не назначай случайную длительность или размер выборки. Не выдавай разницу «до/после» за причинный эффект при изменившемся спросе, ценах, составе клиентов или параллельном внедрении CRM.

Согласуй три разных состояния:

- **Технический результат:** решение работает с нужной точностью/скоростью.
- **Изменение поведения:** люди используют его, процесс действительно меняется.
- **Реализованный финансовый результат:** подтверждено изменение выплат/поступлений относительно альтернативы.

Пропуск любого перехода делает финансовый вывод условным. Ориентиры внедрения и ставки со слайдов не являются универсальными порогами остановки.

## После запуска

1. Приведи план и факт к одному периоду, периметру, валюте, составу затрат и учётной политике. Отдели изменение базы от вклада проекта.
2. Покажи мост «план → объём → цена/ставка → конверсия/производительность → внедрение → затраты → сроки → факт». Для произведения факторов укажи порядок разложения: он влияет на распределение совместного эффекта.
3. Сверь начисленные показатели с деньгами: договор/заказ, факт услуги, поступление/платёж, дебиторка, запасы, CAPEX, долг. Не называй кассовый разрыв убытком без данных о прибыли.
4. Проверь реализацию мощности: какая часть часов снизила закупку/сверхурочные/найм, какая использована на выпуск, какая остаётся резервом. Если доказательств нет, покажи мощность отдельно и денежный эффект как неподтверждённый.
5. Пересчитай прогноз с текущего момента. Для решения «продолжать?» уже понесённые необратимые затраты не должны заставлять продолжать невыгодный проект; при отчёте о полной окупаемости исходного проекта они остаются в исторической сумме.
6. Дай действие: продолжать, изменить механизм, расширить пилот, остановить необязательную часть или собрать конкретные данные. Назови владельца, следующий срок и метрику результата.

## Краткий формат вывода

«По доступным данным [вывод] при [ключевые условия]. Главный драйвер — […]; подтверждено […], пока не подтверждено […]. Денежный эффект [сумма/формула/нет данных], изменение мощности […]. Основной разрыв плана и факта связан с […]. Следующий шаг — [действие владельца], после которого проверяем [показатель/порог]».

Отделяй оценку составителя, наблюдение и договорённость. Формулировки «эффект подтверждён», «бюджет согласован», «проект окупился» требуют соответствующих данных, а не только построенной таблицы.
